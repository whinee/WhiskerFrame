### 2.3 Network & Radio Root Cause Analysis
- **Observed Behavior on Boot:** After cold boot, Wi-Fi radio was reported off until operator issued `nmcli radio all on`.
- **Root Cause Chain Identified:**
  1. **Kernel Modprobe Default:** `/etc/modprobe.d/rfkill_default.conf` contains `options rfkill default_state=0`. Shipped by `raspberrypi-sys-mods`, this instructs the Linux kernel to initialize all wireless devices in a soft-blocked state by default.
  2. **Regulatory Domain Disconnect:**
     - Global regdom: `PH` (set via kernel cmdline `cfg80211.ieee80211_regdom=PH`).
     - Driver phy0 regdom: `country 99: DFS-UNSET`.
     - Broadcom `brcmfmac` firmware requires explicit country configuration; otherwise phy0 remains in restricted world-domain mode.
  3. **Aggressive Wi-Fi Power Saving:**
     - `iw dev wlan0 get power_save` reports `Power save: on`.
     - NetworkManager connection profile `preconfigured` uses `802-11-wireless.powersave: 0 (default)`, which allows 802.11 power management.
     - On Raspberry Pi Zero 2W (Broadcom 43430/43436), Wi-Fi power-save sleep states cause station dropouts under low network activity, failing to wake up or re-associate.
  4. **State Persistence Mechanism:**
     - `systemd-rfkill.service` saves/restores state to `/var/lib/systemd/rfkill/platform-3f300000.mmcnr:wlan`. If an abrupt power loss occurs before an unblocked state is written or if shut down in blocked mode, the system re-arms the block on subsequent boots.
