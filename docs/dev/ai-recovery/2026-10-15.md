## 2. What Changed (Detailed Breakdown)

### 2.1 WS-1: Guest Login UX & nftables Cold Boot Persistence (TSK-11)
- **Problem:** The terminal login screen lacked visual hints for guest demo credentials, causing confusion during stranger evaluation. Furthermore, testing revealed that on cold boot, `nftables.service` was disabled and `/etc/nftables.conf` lacked drop-in support, allowing network egress from the guest account.
- **Changes Applied:**
  - `pi/terminal/login_view.py`: Added `demo_mode: bool = False` parameter to `render_login()`. When active and rows > 4, renders `"demo: guest / guest"` (or `"guest / guest"` on narrow widths) on row `rows - 1` in dimmed ANSI color `theme.ansi[8]`.
  - `pi/terminal/daemon.py`: Extracted `demo_mode` boolean from config (`terminal.login.demo_mode`), defaulting to `True` if `guest` is present in `users`.
  - `/etc/whiskerframe.yaml` & `.whiskerframe.example.yaml`: Configured `demo_mode: true` and added `guest` to `terminal.login.users`.
  - `ansible/roles/guest_demo/tasks/main.yml`: Added task inserting `include "/etc/nftables.d/*.nft"` into `/etc/nftables.conf` and enabled `nftables.service`.
  - Verified live su login: Tested end-to-end PTY spawning running `su - guest` with PAM authentication (`simplepam.authenticate`), confirming shell isolation and session cleanup.

### 2.2 WS-2: CardKB Sticky Ctrl Latch & Cheatsheet (TSK-12)
- **Problem:** M5Stack CardKB lacks a physical Control key, making standard terminal control signals (`Ctrl+C`, `Ctrl+D`, `Ctrl+Z`, `Ctrl+L`) impossible on stock firmware.
- **Changes Applied:**
  - `pi/terminal/bridge.py`:
    - Implemented sequential sticky Ctrl latch on chord `0x8C` (`Fn+Tab`).
    - Armed state sets `_ctrl_armed = True`, tracks `_ctrl_armed_at = time.monotonic()`, and recolors the terminal cursor cell to bright yellow (`theme.ansi[11]` / `0xFF11`, `#ffe08a`) instead of normal cyan.
    - Next alphanumeric key from `_CTRL_VALID_CHARS` (`a-z`, `A-Z`, `@ [ \ ] ^ _ space`) is masked with `& 0x1F` to emit standard C0 control bytes (`Ctrl+C` = `0x03`, `Ctrl+D` = `0x04`).
    - Latch automatically cancels upon 3.0s timeout, toggle press of `Fn+Tab`, or passthrough on non-qualifying keys.
    - Latch is strictly ignored on the login screen to prevent credential corruption.
  - `pi/bin/keys`: Deployed mode 0755 standalone cheatsheet utility wrapped strictly to <=53 columns.
  - `docs/dev/keyboard-cheatsheet.md`: Documented all reachable keys, chords, hex byte outputs, and geometry resize controls (`Fn+Del`).

### 2.3 WS-3: Goodbye Splash Screen & Firmware Sleep Opcode (TSK-13)
- **Problem:** Unclean shutdowns or lack of visual feedback during poweroff left users uncertain if the cyberdeck had halted safely.
- **Changes Applied:**
  - `pi/bin/goodbye_hook`: Deployed Python CLI tool supporting `--mode auto|shutdown|reboot` and `--dry-run`.
    - Reads `/opt/cyd-display-link/assets/images/cess/lyra-doodle-transparent.png`.
    - Composites doodle over theme background color (`0x18C5`) with bold text `"bai baiii"` (shutdown) or `"brb"` (reboot).
    - Serializes as centered 128x128 image chunk (`0x05` `DRAW_IMAGE`) at (96, 56).
    - Holds for ~4 seconds, then wipes screen to black (`0x0000`) with a single `DrawRect` frame.
    - Total execution strictly capped under 7.5 seconds with fail-silent error handling.
  - `/etc/systemd/system/cyberdeck-goodbye.service`: Registered oneshot systemd unit triggered before `shutdown.target`, `reboot.target`, `poweroff.target`, and `halt.target`.
  - `whiskerframe/protocol.py` & `whiskerframe/terminal.py`: Added additive wire opcode `0x06` (`OPCODE_SLEEP` / `DisplaySleep`) for low-power coprocessor display blanking (DISPOFF/SLPIN, backlight off, 80MHz CPU).
  - *Firmware Flashing Gate:* Safely parked ESP32 physical flashing per safety SOP due to absence of local `esptool` on the Pi and sealed chassis constraints.

### 2.4 WS-4: Terminal Network UX (TSK-14)
- **Problem:** Standard `nmcli` commands output lines far exceeding 80 columns, causing unreadable wrapping on the 53x30 display.
- **Changes Applied:**
  - `pi/bin/wifi`: Deployed mode 0755 Python CLI tool providing:
    - `wifi`: Displays active connection status, SSID, IPv4 address, and saved profiles within 53 columns.
    - `wifi scan`: Scans 2.4 GHz channels, dedupes by SSID, ranks top 10 by signal strength, and formats a clean table `[#] SSID SIGNAL SECURITY`.
    - `wifi join <#|SSID>`: Prompts for passphrase with hidden input and connects via NetworkManager.
    - `wifi forget <SSID>`: Deletes saved connection profiles.
  - `docs/dev/network-access.md`: Authored comprehensive networking manual covering 2.4 GHz only hardware constraints of the Pi Zero 2W, phone hotspot setup, laptop-hosted 2.4 GHz fallback, and client isolation workarounds.

### 2.5 WS-5: Offline Documentation & Wiki Helper (TSK-15)
- **Problem:** The deck requires offline documentation access while operating without network connectivity.
- **Changes Applied:**
  - `pi/bin/wiki`: Deployed mode 0755 Python CLI tool providing 53-col formatted documentation queries.
    - First attempts `kiwix-serve` on `http://127.0.0.1:8088`.
    - Falls back cleanly to local man pages (`man`) and bash documentation (`help`).
    - Strips ANSI formatting and wraps text strictly to <=53 columns with interactive paging.
  - Pi Packages: Installed `bash-doc` and `w3m` on the Pi.
  - `docs/dev/offline-library-plan.md`: Authored staging plan for downloading Simple English Wikipedia ZIM (~1.1 GB) on operator laptop to protect Pi thermal and battery envelopes.

### 2.6 WS-6: Phone Hotspot 2.4 GHz Verification
- **Problem:** The Pi Zero 2W lacks 5 GHz Wi-Fi hardware. The companion Redmi Note 12 hotspot needed verification on the 2.4 GHz band without dropping the Pi's active home Wi-Fi link.
- **Changes Applied:**
  - `~/.local/bin/adb-safe`: Built restricted wrapper (mode 0755) allowing only whitelisted input and settings inspection commands.
  - Automated inspection verified:
    - Screen unlocked and Settings intent executed safely.
    - Wi-Fi tethering set to 2.4 GHz band (AP Band Channel 1 / 2412 MHz).
    - Hotspot verified via read-only Pi scan (`wpa_cli scan_results` detected `Redmi Note 12` at 100% signal strength).
    - Phone Wi-Fi restored, hotspot disabled, and screen returned to home launcher.

## 3. What's Risky & Residual Hazards

1. **CardKB Sticky Modifier Discovery:**
   - *Risk:* Strangers touching the device at the demo venue may not intuitively know that `Fn+Tab` latches the Control key.
   - *Mitigation:* The `keys` command prints a concise cheatsheet in <=53 columns. The cursor cell visibly shifts to bright yellow (`#ffe08a`) when Ctrl is armed, providing clear visual feedback.
2. **Guest Network Containment:**
   - *Risk:* Demonstrators attempting network commands (`curl`, `ping`) will receive immediate kernel drop errors.
   - *Mitigation:* This is an intended security boundary (REQ-OPS-04). The `demo` command explains available local tools, and ephemeral storage isolates user doodles or scripts.
3. **ESP32 Firmware Sleep Opcode Parked:**
   - *Risk:* The CYD coprocessor remains powered and running at normal clock during shutdown until physical power is removed by the UPS switch.
   - *Mitigation:* The `goodbye_hook` leaves the display framebuffer completely black (`0x0000`), drawing minimal power and preventing screen burn-in. Flashing the ESP32 coprocessor firmware is safely deferred to an open-case session.
4. **Temporary Password Exposure:**
   - *Risk:* The temporary recovery password (`u472bmt`) was held in memory during the recovery session.
   - *Mitigation:* Password rotation is prominently scheduled as Step 5 in the Operator Morning Checklist.
