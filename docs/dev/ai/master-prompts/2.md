## Required outcomes
1. **Terminal geometry:** Fix resize/geometry changes so all terminal text is correctly reflowed and redrawn without missing text, stale cells, clipping, or corruption.
2. **Independent display layers:** Give the terminal and status bar separate, non-overlapping regions with strict redraw/clipping ownership. Add a global overlay layer reserved for splash, reboot, and poweroff screens. Test layer ownership, z-order, geometry changes, invalidation, and redraw isolation.
3. **i3-like configurable status bar:** Configure placement, segments, formatting, refresh intervals, and safe data sources. Support per-user profiles. Login screen may expose only safe public values such as time, battery percentage, and Wi-Fi/LTE signal percentage when available. After login, expose role-appropriate values (e.g. workspace state for root) without leaking privileged data to `neko` or `guest`. Validate configuration and provide safe fallbacks.
4. **Guest workspaces:** Allow guest-created workspaces without weakening the sandbox. Test authorization, filesystem isolation, network egress, resource limits, process and logout cleanup, and escape attempts.
5. **Keyboard, NeoPixel, and transport:** Diagnose Fn+Tab not flashing yellow and the rear NeoPixel staying red. Trace the actual key event, firmware command, protocol, LED state machine, and physical behavior. Determine whether Pi↔ESP32 CYD USB-C UART communication works and whether Wi-Fi/Bluetooth collaboration is implemented and works on hardware. Benchmark latency, throughput, and screen refresh before claiming improved speed; preserve protocol compatibility.
6. **Screen observability:** Determine exactly what the agent can observe on the physical display. Inspect available screenshot/framebuffer/serial capture paths and create/document a reproducible visual verification path if feasible. Never claim visual inspection without captured evidence.
7. **Strict testing:** Add focused unit, integration, regression, and E2E coverage for every outcome above. Run the relevant full suite and safe hardware tests. Tests must verify behavior, not merely source strings.

## Completion gate
Track each outcome to implementation, tests, and evidence. Maintain a concise task ledger and durable handoff. Mark each item **PASS**, **FAIL**, **BLOCKED**, or **NOT TESTED**. If work remains, continue implementation rather than ending with a plan. No push, release tag, or publication.
