# Master Prompt #3 — One-Hour Cyberdeck Recovery

## Mission and deadline

Restore a good-looking, consistent WhiskerFrame font; recover the missing local `.whiskerframe.yaml`; and make the PC-side preview genuinely work so agents can inspect what the cyberdeck renders. Work to a one-hour deadline: prioritize these three outcomes over unrelated work. Do not end with a plan or a success recap unsupported by evidence.

## First: preserve and inspect

1. Load the user's available personal context. Read `docs/dev/ai/master-prompts/1.md`, `docs/dev/ai/master-prompts/2.md`, the latest `docs/dev/ai-agent-handoff.md`, repository instructions, `.agents/skills/git-github-workflow/SKILL.md`, and the documented Orca orchestration and Claude hook skills.
2. Inspect `git status`, branch/HEAD, diffs, stashes, worktrees, active workers, deployment queue/lock, `justfile`, `.claude/settings.json`, preview code, font assets, and recent Git history. Aggressively fan out independent, unblocked investigations using the documented Orca skill.
3. **Do not run deployment until configuration is safe.** The user's local `.whiskerframe.yaml` is missing. Check ignored/untracked files, Git history, backups, deployed config, and existing copies. Recover the user's real configuration without exposing secrets, overwriting a newer copy, or substituting `.whiskerframe.example.yaml` with its placeholders. If exact recovery is impossible, preserve every candidate and report the safest recovery path. Never silently create a default config that changes login, guest, network, or security settings.
4. Preserve every user change and worktree. No reset, clean, destructive deletion, force-push, release tag, or publication. No reboot/poweroff without explicit authorization.

## Priority A — Restore the original font

- Use Git history, prior previews/specimens, original assets, and earlier agent changes to identify and restore the last known-good font/rendering implementation. Do not guess what “old font” means when repository evidence can establish it.
- The user prefers rounded fonts. Prefer the original project-made font if recoverable; consider GNU Unifont only if the original cannot be recovered and a real preview demonstrates it is better.
- Establish one authoritative glyph renderer and metrics source for all supported geometries (53×30, 40×20, 26×15, 17×10), terminal, status bar, cursor, and preview. Prevent inconsistent cell sizes, baselines, wrapping, clipping, and reflow.
- Generate actual saved preview images and grid dumps for every geometry. Inspect them visually; compare against known-good specimens. Add meaningful regression tests without replacing visual verification with tests alone.

## Priority B — Fix the PC preview/mirror

- Trace the current `scripts/desktop_mirror.py`, `whiskerframe.preview.PreviewRenderer`, display protocol, serial connection, and keyboard forwarding. Diagnose why `python scripts/desktop_mirror.py --port /dev/ttyUSB0` exits after “Bridge ready” without a visible/working preview, or why the screen does not update.
- Find the original PC-side preview command in Git history/docs and restore it if sound. Make the viewer visible, continuously update from the same authoritative display/rendering path as the physical CYD, and show connection/error status. Support graceful shutdown and actionable diagnostics.
- Implement and verify PC keyboard forwarding without duplicate input, preserving CardKB/Fn+Tab semantics and key ordering. Bind control endpoints to localhost unless a deliberate authenticated alternative is required.
- The ILI9341 serial protocol may be write-only. Do not claim LCD readback or pixel-perfect physical capture without evidence. Clearly distinguish a faithful shared-renderer mirror from camera/hardware capture.
- Add a Justfile recipe for launching, stopping, and checking the viewer. Test the actual user command and confirm a visible window/frame updates—not merely that initialization prints “Bridge ready.”

## Priority C — Safe activation and verification

- Inspect why the deployment hook and `just apply` might have left the font/preview wrong. Verify which files are deployed, which process uses them, and whether the hook can deploy incomplete edits or mishandle missing config. Fix relevant hook/Justfile behavior only as needed; avoid unrelated refactoring.
- Run focused tests, then the full relevant suite if time allows. Use the existing documented Justfile workflow. Do not bypass preflight or flash firmware unless firmware changed and the normal safe flash gates pass.
- After config recovery and preflight, deploy and activate the intended runtime changes using the existing workflow. Verify the active service and deployed file identity. Then run the PC viewer and exercise the physical display where available.
- If a safe deployment cannot be completed within the deadline, leave the last known-good device runtime intact, keep the fix local, and report exact blockers. Never claim deployment or physical verification without evidence.

## Completion gate

Return a concise ledger for: (1) font restoration/geometry consistency, (2) local config recovery, (3) working PC preview and keyboard forwarding, and (4) deployed/runtime verification. Each must be `PASS`, `FAIL`, `BLOCKED`, or `NOT TESTED`, with exact files/commits, commands, results, preview artifact paths, and remaining issues. Continue implementing fixes; do not stop at diagnosis. Keep changes local unless separately authorized to publish.
