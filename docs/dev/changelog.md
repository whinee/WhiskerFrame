### Changed

- `memory_safety` role made **btrfs-aware** and **deployed + verified live** on the Pi (TSK-07, 2026-10-07): the 512MB swapfile is now created with `btrfs filesystem mkswapfile --size 512M --uuid clear` on the `@swap` subvolume (mounted `/swap`, `noatime`, no compress), `nodatacow` (verified `lsattr` `C`), `chmod 0600`, fstab `pri=10 nofail` — a plain `fallocate`+`mkswap` is illegal on btrfs (CoW is incompatible with swap). The role now **detects and adopts** an already-active zram swap (the Pi's native `systemd-zram-setup@zram0`, zstd, pri=100) instead of installing `zram-tools`, which had created a conflicting second manager that failed on the busy device (same two-manager class of bug as wlan0); `zram-tools` is installed only when no zram swap exists. Verified live: `zram0` pri=100 outranks `/swap/swapfile` pri=10, `vm.swappiness=15`/`vfs_cache_pressure=60`, earlyoom active (`-m 8 -s 8`); asserts the btrfs SSD mount and refuses `/`,`/boot`,`/boot/firmware`. Idempotency: `swapon` `failed_when` now tolerates `busy` as well as `already`. Rationale in `docs/dev/ai-decisions.md` DEC-W12.
- `native_services` role **deployed + verified live** on the Pi (TSK-07, 2026-10-07, secretless parts): **syncthing@neko** active as user `neko` (not root — syncthing refuses root; default user was wrongly `ansible_user=root`), `MemoryMax=200M`, GUI bound 127.0.0.1:8384; **filebrowser** active as `neko` (native pinned binary v2.31.2, not Docker), `MemoryMax=128M`, HTTP 200 on 127.0.0.1:8080 (fixed a stale root-owned db by defaulting `user=neko` + recursive chown); **netbird** installed + active, `MemoryMax=150M`, status `NeedsLogin` → **BLOCKED-ON-OPERATOR** (needs a setup key / interactive SSO; none invented); **git** dedicated account with `/usr/bin/git-shell` and bare-repo root on the SSD, `authorized_keys` empty → **BLOCKED-ON-OPERATOR** (needs operator SSH pubkey; none invented). Git stays plain bare repos over SSH (no Forgejo); repos on the SSD, never inside Syncthing folders. Rationale in `docs/dev/ai-decisions.md` DEC-W11.

### Changed

- Changed the battery daemon's `auto_shutdown` to default to `true`: at/below `critical_percent` (5%) the daemon now requests a clean `systemctl poweroff` to protect the pack. The `.whiskerframe.yaml` `ups: auto_shutdown` key and the `DaemonConfig.auto_shutdown` fallback are both `true`. A spurious INA219 reading at <= 5% could therefore trigger a real poweroff; set `auto_shutdown: false` and restart the daemon to disable (see `docs/dev/debug.md`).
- `scripts/pi_env_check.py` constants (`PI_HOST`, `PI_USER`, `DEFAULT_KEY_PATH`, `DEFAULT_VENV_PATH`, `COMPONENTS`) are now sourced from `.env` / `.whiskerframe.yaml` via `scripts/config.py` rather than being hard-coded.

Added `build_probes` and `DEFAULT_VENV_PATH`.

It is only used by dev-time tooling (`dev/scripts/py/gen_config.py`, `justfile`), never by the `whiskerframe/` runtime, and it transitively pulls `jsonnet` (a C++ build) that exhausted memory when building on the Raspberry Pi Zero 2W.   - `pi.terminal.bridge.KeyQueue`: added non-blocking background queue adapter over CardKB key iterator, unfreezing the `_ShellSession` pump loop so Linux MOTD greetings, shell prompts, and background output render instantly without requiring keypresses.
  - `pi.terminal.bridge.TerminalBridge`: added `Fn + Backspace` (`0x7F`, Del on CardKB) to `RESIZE_CHORDS` alongside `Ctrl+]` (`0x1D`) to toggle terminal font size.
  - `pi.terminal.grid.Grid`: added `render_with_cursor` to render an inverted/highlighted block cursor at `(cursor_row, cursor_col)`.
  - `pi.terminal.bridge.TerminalBridge`: translated CardKB arrow key codes (`0xB5`, `0xB6`, `0xB4`, `0xB7`) to VT100 ANSI escape sequences (`\x1b[A`, `\x1b[B`, `\x1b[D`, `\x1b[C`), and mapped Enter (`0x0D`) to `\n` (`0x0A`) for single-press command execution.
  - Initial shell render: `_ShellSession` now reads initial shell output before the first frame paint, displaying the shell prompt and block cursor immediately upon login without requiring a keypress.
  - Customized Pi shell prompt via `/etc/profile.d/cyd_prompt.sh`: displays `r# ` for `root` and `n$ ` for `neko`.
- `cyd-terminal` login flow fixes:
  - `pi.terminal.login.LoginState`: added `_KEY_LEFT` (`0xB4`) and `_KEY_ESC` (`0x1B`) key handling on the password screen to instantly return to the user selection screen and clear the password buffer (`clear_password`).
  - `pi.terminal.bridge.TerminalBridge`: fixed authentication failure handling so wrong password entries flash a `"wrong password"` error on the password screen for 3.0 seconds without triggering account lockouts or dropping back to user selection prematurely; after 3 seconds, the error clears and the password prompt resets cleanly for re-entry.
- CYD terminal: corrected the configured login users to the Pi's real accounts (`root`, `neko`); the placeholder `lyra` is not a system user and PAM rejected it with 'user unknown'.
- CYD terminal: every full repaint (login screen, session start, post-reopen, keyframe) now clears the whole panel to the theme background first, so the boot splash no longer bleeds through the login/shell text (full_repaint intentionally skips blank cells).
- Firmware: added `tft.invertDisplay(true)` in setup — this CYD panel rendered every colour as its complement (red<->cyan, white<->black) under the default TFT_eSPI config; empirically confirmed with pure RGB565 primaries on-device.
- Fixed the battery percentage/current/status freezing: a transient INA219 I2C error put the daemon into a 30s backoff during which `status.json` showed stale values; the window is now short, flagged stale, and recovers by reopening+recalibrating the chip.
- Corrected the UPS INA219 I2C address in the hardware docs from `0x42` to `0x41` (the address detected on this build via `i2cdetect -y 1`).
- `pi_env_check.ssh_run` now shell-quotes the remote command into a single string (SSH re-parses trailing args through the remote login shell, which was word-splitting the probe script and causing a syntax error near `then`). The pip probe also accepts venv `python -m pip`, system `python3 -m pip`, or `pip3`/`pip`, since uv-managed venvs ship without pip by design.
- `pi_env_check` probes now run through a non-login `sh -c` (not `bash -lc`), so the Pi's shell rc files are never sourced. Sourcing them made each SSH probe hang until timeout (~30s total) and mis-report every component as missing; probes now return promptly and detect the venv runtime correctly.
- `whiskerframe.coordinates.FourXY` now accepts any axis-aligned rectangle, not only squares; the vertex validation checks two equal short sides, two equal long sides, two equal diagonals, and the Pythagorean relation, and width/height are taken from the bounding-box extents so orientation is preserved.
