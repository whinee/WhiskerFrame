# API Documentation Maintenance

This rule governs how AI agents must document API changes in `whiskerframe/` Python Source Files, so that it may be reflected properly in `docs/api/unreleased`, and keep documentation synchronized with codebase modifications and `docs/dev/changelog.md`.

## Generation and Architecture

API documentation inside `docs/api/unreleased` is generated by `pdoc` via the `just docs` command:

- **Source of Truth**: Python source code docstrings and type annotations in `whiskerframe/`.
- **Output Target**: Markdown documents inside `docs/api/unreleased/`.
- **Handbook & Guides**: Developer handbook documents in `dev/docs/` are copied to `docs/api/unreleased/dev/`.

## Docstring and Markdown Grammar Standards

When modifying or introducing API interfaces in Python source files:

1. **Imperative Mood**: Use concise, active voice in docstrings (e.g., "Render barcode or QR code within specified coordinates", "Validate text anchor format").
2. **Type Annotations**: All function/method parameters and return types must be explicitly typed using standard Python type hints.
3. **Docstring Formatting**: Strictly adhere to the template defined in `dev/tpl/others/autodoc.mustache`:
   - **Modules**: Overview summary on the first line.
   - **Classes**: Purpose summary, model configuration details, and usage expectations.
   - **Functions and Methods**: Minimum 3 lines following `dev/tpl/others/autodoc.mustache` structure:
     - Imperative summary on the first line ending with a period.
     - Optional extended description separated by a blank line.
     - `Args:` section with bullet points:
       - Positional: `- <var> (<type>): <description>`
       - Optional: `- <var> (<type>, optional): <description>. Defaults to <default>.`
     - `Raises:` section with bullet points:
       - `- <ExceptionType>: <description>`
     - `Returns:` section:
       - `<ReturnType>: <description>`
     - `Yields:` section:
       - `<YieldType>: <description>`
     - Trailing blank line before closing `"""`.

   Template reference from `dev/tpl/others/autodoc.mustache`:

   ```text
   Summary description.

   Extended description if necessary.

   Args:
   - var (`type`): Description of variable.
   - kwarg (`type`, optional): Description of kwarg. Defaults to `default`.

   Raises:
   - `ExceptionType`: Description of when exception is raised.

   Returns:
   `ReturnType`: Description of return value.

   ```

## General Workflow for API Updates

Follow these required steps whenever API changes occur:

1. **Verify API Currency**:
   - Ensure all old/existing and new/modified symbols, classes, attributes, and methods have accurate docstrings and type hints in the source code.
2. **Verify Changelog Currency**:
   - Check if the unreleased section in `docs/dev/changelog.md` (`## <X.Y.Z> (Unreleased)`) accurately records every API change.
   - If missing changes, update `docs/dev/changelog.md` immediately according to `.agents/rules/changelog.md`.
3. **Verify Dev Notes (`docs/api/unreleased/`) Currency**:
   - Check if the unreleased API dev notes in `docs/api/unreleased/` accurately concurs with how the API should be used and consumed.
   - If outdated, update `docs/api/unreleased/ immediately.
4. **Execute `just docs`**:
   - Run `just docs` to rebuild `docs/api/unreleased`.
   - `just docs` automatically triggers `just lint`.
4. **Fix Errors and Iterate**:
   - If `just docs` reports any generation errors, docstring warnings, or lint failures, resolve them immediately.
   - Repeat `just docs` until the command succeeds with zero errors and zero warnings.
